# NFR Design Patterns — UoW-1（基盤構築）

NFR Requirements の 44 要件を、設計パターンとして具体化する。

---

## 1. 適用するパターン

### P-1: ミドルウェアによる横断的関心事の適用（セキュリティヘッダ）

**対象要件**: NFR-S1 / U1-SE-1 / SECURITY-04
**根拠**: ADR-015

**設計**

```
Request -> [SecurityHeaders] -> Router -> PortfolioController -> Response
                  |
                  +-- config/security.php のヘッダ定義をレスポンスに適用
```

- ヘッダ値は `config/security.php` に持ち、ミドルウェアはそれを適用するだけにする
- 全ルートに適用する（`web` ミドルウェアグループ）
- HTML を返す経路は必ず Lambda を通るため、CloudFront 経由・API Gateway 直アクセスの
  いずれでもヘッダが付く

**検証**: Feature テストで、設定ファイルの各ヘッダが実レスポンスに存在することを確認する。

### P-2: 多層キャッシュ（TTL の使い分け）

**対象要件**: U1-PF-3 / U1-PF-4 / NFR-S9
**決定**: Q2 = B

| 対象 | Cache-Control | CloudFront TTL | 根拠 |
|---|---|---|---|
| 静的アセット `/build/*` | `public, max-age=31536000, immutable` | 1 年 | Vite がファイル名にハッシュを付けるため、内容が変われば URL が変わる |
| HTML（`/`） | `public, max-age=60` | 60 秒 | 連続アクセスを CloudFront が吸収する。デプロイ後の反映遅延は最大 60 秒 |

**設計判断**: HTML の Invalidation を行わない。
60 秒の反映遅延を受け入れることで、デプロイ手順に無効化のステップを増やさずに済む。
Invalidation は月 1,000 パスまで無料だが、手順が増えること自体を避けた。

**濫用対策としての効果**: 同一コンテンツへの連続アクセスは 60 秒に 1 回しか
Lambda に到達しない。ただし **API Gateway への直アクセスはこの経路を迂回する**（ADR-015 の既知事項）。

### P-3: 上限による費用の頭打ち（Bulkhead に相当）

**対象要件**: U1-SC-2 / NFR-S9 / SECURITY-11
**根拠**: ADR-013

```
Lambda 予約済み同時実行数 = 10
  -> 上限到達時は 429 を返す（Q4 = A。カスタムページは作らない）
  -> 同時に、AWS Budgets が 1 USD 到達でメール通知
```

**設計判断**: レート制限（WAF）ではなく同時実行数の上限を使う。
守るべきものが費用である以上、費用の総量に上限を与える方が要件に直接効く。
**可用性を犠牲にして費用を守る選択**であることを明示しておく。

### P-4: 構造化ログ + 相関 ID

**対象要件**: U1-OB-1 / U1-OB-2 / SECURITY-03
**決定**: Q4 = A（JSON 形式）、Q5 = A（Lambda リクエスト ID）

```
Monolog
  -> JsonFormatter
  -> stderr
  -> CloudWatch Logs（保持 14 日: ADR-014）
```

**ログの共通項目**

| キー | 内容 | 取得元 |
|---|---|---|
| `timestamp` | ISO 8601 | Monolog |
| `level` | ログレベル | Monolog |
| `message` | メッセージ | 呼び出し元 |
| `request_id` | **Lambda のリクエスト ID** | Bref のコンテキスト |

**実装上の注意**: Lambda リクエスト ID はローカル環境では取得できない。
取得できない場合は UUID にフォールバックする設計とし、
「本番では CloudWatch の REPORT 行と突き合わせられる」「ローカルでも相関は取れる」の
両方を満たす。

**禁止事項**: シークレット・トークン・PII をログに出力しない（SECURITY-03）。
本ユニットでは該当する値を扱わないが、規約として明記する。

### P-5: グローバルエラーハンドラ + 汎用エラー表示

**対象要件**: U1-RL-1 / U1-RL-2 / NFR-S6 / SECURITY-09, 15
**決定**: Q3 = B（Inertia のエラーページ）

```
未捕捉例外
  -> bootstrap/app.php の例外ハンドラ
  -> 構造化ログに記録（スタックトレースを含む）
  -> Inertia でエラーページをレンダリング（固定文言のみ）
```

**設計**
- 本番（`APP_DEBUG=false`）では、ステータスコードに応じた固定文言のみを表示する
- スタックトレース・内部パス・フレームワークバージョンを画面に出さない
- ローカルでは Laravel の既定のデバッグ画面を使う（`APP_DEBUG=true`）

**フェイルクローズの適用**: コンテンツを推測して補完しない。
取得できないものは「読み込めませんでした」と表示する（Application Design の失敗設計と同じ方針）。

### P-6: 設定の外部化と環境差の吸収

**対象要件**: U1-MT-1 / U1-MT-2 / U1-SE-10

| 設定 | ローカル（Sail） | 本番（Lambda） |
|---|---|---|
| `APP_ENV` | `local` | `production` |
| `APP_DEBUG` | `true` | `false` |
| キャッシュストア | `array`（無効相当） | `file`（`/tmp` 配下） |
| ログ出力先 | `stderr`（Sail のログ） | `stderr`（CloudWatch Logs） |
| ログ形式 | JSON | JSON |
| セッション | 使わない | 使わない |

**注意**: Lambda 上で書き込み可能なのは `/tmp` のみ。
`storage/` 配下への書き込みが発生する設定（ファイルキャッシュ、ビューキャッシュ、ログファイル）は
全て `/tmp` に向けるか無効化する。**Infrastructure Design で `serverless.yml` の環境変数として確定する。**

## 2. 適用しないパターンとその理由

| パターン | 不採用の理由 |
|---|---|
| **リトライ / 指数バックオフ** | 外部依存が存在しない。リトライ対象の呼び出しがない |
| **サーキットブレーカ** | 同上。遮断する対象がない |
| **フェイルオーバ / マルチリージョン** | 可用性目標を設定していない（U1-AV-1）。単一リージョン構成（Q1 = A） |
| **ヘルスチェック / 自動復旧** | 状態を持たないため、異常時の復旧は再デプロイで足りる（U1-AV-2） |
| **キューによる非同期化** | 非同期処理が存在しない。UoW-4 の拡張ポイントに図示するのみ |
| **WAF によるレート制限** | 月 5〜8 USD の固定費が NFR-1 と衝突する（ADR-013） |
| **プロビジョンド同時実行** | 固定費が発生する。コールドスタートの数値目標を持たない（U1-PF-5） |
| **CloudFront Invalidation** | HTML の TTL を 60 秒にしたため不要（P-2） |
| **オリジン遮断（共有シークレット）** | ADR-015 で不採用。既知の未対応事項として拡張ポイントに記載 |
| **分散トレーシング（X-Ray）** | 計測要件を削除済み。トレース対象のスパンが実質 1 つしかない |
| **セキュリティイベントアラート** | 認証イベントが存在しない（SECURITY-14 の該当項目は N/A） |

**この表の意図**: 「使わなかったパターン」とその理由を残すこと自体が、
本サイトの訴求（制約の中でどう判断したか）に直結する。
構成図の拡張ポイントの説明に流用できる。

## 3. 既知の未対応事項

| # | 内容 | 影響 | 対応時期 |
|---|---|---|---|
| K-1 | **API Gateway の URL への直アクセスで CloudFront のキャッシュを迂回できる** | Lambda 実行回数が増える経路が残る。費用は同時実行上限で頭打ち | 必要が生じた時点で ADR-012 の方式（共有シークレットによるオリジン遮断）を導入。**構成図の拡張ポイントに含める**（Q1-b = B） |
| K-2 | 静的アセットにセキュリティヘッダが付かない | SECURITY-04 の対象外のため要件上の問題はない | 対応しない |
| K-3 | Lift の `server-side-website` の設定可能範囲を未確認 | Infrastructure Design で実物を確認する必要がある | Infrastructure Design（次ステージ） |

## 4. Security Compliance（NFR Design ステージ）

| Rule | 判定 | 根拠 |
|---|---|---|
| SECURITY-01 暗号化 | **準拠** | S3 の暗号化・パブリックアクセスブロックは Infrastructure Design で具体化。TLS は CloudFront が終端 |
| SECURITY-02 アクセスログ | **準拠** | U1-OB-5。設定は Infrastructure Design |
| SECURITY-03 アプリログ | **準拠** | P-4（JSON 構造化ログ、相関 ID、禁止事項の明記） |
| SECURITY-04 セキュリティヘッダ | **準拠** | P-1。HTML を返す全経路が Lambda を通るため漏れがない（ADR-015） |
| SECURITY-05 入力検証 | **N/A** | 入力パラメータが存在しない |
| SECURITY-06 最小権限 | **準拠（例外あり）** | Lambda 実行ロールは最小。デプロイ用ポリシーのワイルドカードは ADR-012 に記録した例外を継続 |
| SECURITY-07 ネットワーク | **N/A** | VPC 不使用 |
| SECURITY-08 アクセス制御 | **N/A** | 認可対象のリソースが存在しない |
| SECURITY-09 ハードニング | **準拠** | P-5（本番でのエラー秘匿）、P-6（`APP_DEBUG=false`） |
| SECURITY-10 サプライチェーン | **準拠** | U1-SE-12, U1-SE-13。手順は Build and Test で具体化 |
| SECURITY-11 セキュア設計 | **準拠** | P-2 + P-3 の組み合わせでレート制限に代替。**濫用ケースの想定**: ① 大量リクエストによる課金増加 → 同時実行上限で頭打ち ② オリジン迂回によるキャッシュバイパス → K-1 として記録し、同時実行上限で費用は担保 |
| SECURITY-12 認証 | **N/A** | ユーザー認証が存在しない。共有シークレットの取り扱いは ADR-015 により不要になった |
| SECURITY-13 完全性検証 | **準拠** | 外部 CDN を使わない。非信頼データのデシリアライズなし |
| SECURITY-14 アラート・監視 | **部分的に適用外** | ログ保持要件は ADR-014 により適用外（14 日）。他項目は適用 |
| SECURITY-15 例外処理 | **準拠** | P-5（グローバルハンドラ、フェイルクローズ、汎用メッセージ） |

**ブロッキング所見: なし。**
