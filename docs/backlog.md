### P-2 の対応内容（2026-08-23）

**案 B（独自キャッシュポリシー）を採用。TTL は当初案の 60 秒ではなく 5 秒。**

| 判断 | 理由 |
|---|---|
| 案 A（`CachingOptimized`）ではなく案 B | `CachingOptimized` は DefaultTTL が 1 日。オリジンが `Cache-Control` を返し損ねた瞬間に 1 日キャッシュされる。**MaxTTL を 5 秒で固定できる独自ポリシーの方が事故が起きない** |
| 60 秒 → **5 秒** | 「キャッシュ無し → 5 秒」で削減効果のほとんどが取れる。5 秒でも 1 エッジあたり Lambda 到達は 0.2 回/秒に落ちる。**費用の天井はアカウント同時実行上限 10 が既に担保**しており、そこから先を絞る意味が薄い |
| 5 秒の副次的な利点 | `versionedAssets` を使っていないため、デプロイで古いアセットが消える。HTML を長く保持すると消えた JS を指し続けて画面が壊れるが、5 秒ならその窓が実質無視できる。**デプロイ結果の確認も待たされない** |

**キャッシュキーに `X-Inertia` ヘッダを含めている。** 現状 Inertia のクライアント遷移は使っていないが、
将来 `<Link>` を入れると同じ URL で HTML と JSON が返り分かれるため、後から気づくと事故になる。

## 7. 運用上の注意（踏んだ罠の記録）

| # | 内容 |
|---|---|
| 1 | **コンテナ内でファイルを作る操作は `-u sail` で行う。** root で実行すると `vendor/` `node_modules/` が root 所有になり、`sail` の各コマンドが軒並み `EACCES` で失敗する |
| 2 | **デプロイは `./bin/deploy.sh` を使う。** `composer install --no-dev` は `laravel/sail` 自体を消すため、その後 `sail ...` を呼ぶ手順は必ず失敗する |
| 3 | **AWS はアカウントの Lambda 同時実行上限を自動で引き上げることがある。** 引き上げられると ADR-016 の「費用の天井」が消える。`aws lambda get-account-settings` で現在値を確認できる |
| 4 | 設定ファイル（`config/*.php`）の中で `app()` を呼ばない。読み込み時点ではコンテナが未準備 |
| 5 | **`public/` に置いた静的ファイルは、`serverless.yml` の Lift `assets` に書かないと本番で 404 になる。** Lift は `/build/*` しか S3 に配信せず、それ以外は Lambda に流れる |
