# 要件定義

## 1. ゴール

サイトを見た人が、**技術構成について直接質問したくなる**状態をつくる。

「見た目がきれいですね」で終わらせない。
「なぜデータベースを使わなかったのか」「なぜ osls を選んだのか」を
聞きたくなることをもって成功とする。

そのために、技術力の証明を「作れる」ではなく **「選べる」** に置く。
何が作れるかではなく、制約の中でどう判断したかを見せる。

## 2. 非ゴール

- 機能の多さ（認証・CRUD・管理画面などは差がつかない）
- デザインのオリジナリティ勝負（見やすさが担保できれば十分）
- 実務案件の詳細（職務経歴書の役割。重複させない）

## 3. 非機能要件

| ID | 要件 |
|---|---|
| NFR-1 | 月額固定費をゼロに近づける（目標: 月 100 円以下） |
| NFR-2 | RDS・NAT Gateway・ALB を使用しない |
| NFR-3 | ライセンス費用・アカウント登録が不要なツールで構成する |
| NFR-4 | スマートフォンでの閲覧に耐えること |
| NFR-5 | 独自ドメインは取得しない。CloudFront のデフォルトドメインで公開する |
| NFR-6 | サーバサイドは要件が生じるまで実装しない。生じた場合に Lambda 関数の追加で拡張できる状態を保つ |

### セキュリティ非機能要件

AI-DLC の Security ベースライン拡張を有効にしたことによる要件（ADR-010）。
括弧内は対応する SECURITY ルール ID。

| ID | 要件 |
|---|---|
| NFR-S1 | HTML を返す全レスポンスに CSP・HSTS・X-Content-Type-Options・X-Frame-Options・Referrer-Policy を付与する（SECURITY-04） |
| NFR-S2 | CloudFront と API Gateway のアクセスログを有効にする（SECURITY-02） |
| NFR-S3 | アプリケーションログを構造化し、CloudWatch Logs に集約する。ログ保持期間を 90 日以上に設定する（SECURITY-03, SECURITY-14） |
| NFR-S4 | IAM ポリシーは最小権限とし、ワイルドカードのアクション・リソースを使わない（SECURITY-06） |
| NFR-S5 | 依存はロックファイルで固定し、脆弱性スキャンをビルド手順に含める。Docker イメージタグを `latest` で固定しない（SECURITY-10） |
| NFR-S6 | 本番でスタックトレース・内部パス・フレームワークバージョンを返さない。グローバルエラーハンドラを持つ（SECURITY-09, SECURITY-15） |
| NFR-S7 | S3 バケットはパブリックアクセスをブロックし、CloudFront 経由でのみ配信する（SECURITY-01, SECURITY-09） |

**NFR-1 との関係**: NFR-S2・NFR-S3 はログ保存に伴う費用が発生する。この規模では
月額数円〜十数円の範囲に収まる見込みで、NFR-1 の「月 100 円以下」とは両立する。
両立しないことが判明した場合は ADR-010 を見直す。

## 5. サイト構成

### S-1. Hero

- サイト名: **HK Portfolio**
- キャッチ: **月額 100 円未満で動く、サーバレスなポートフォリオ**
- リポジトリへのリンク: https://github.com/h-kusaba-1001/portfolio2026
- 下部に S-2 への導線

Hero の文言とリンクは React コンポーネントに直接持つ（Markdown 化しない）。
分量が少なく、更新頻度も低いため。US-7 の「コードを触らずに更新」の対象は S-2〜S-5 とする。

Lambda の月 100 万リクエストと CloudFront のデータ転送には永年無料枠があるため、
構成上は 0 円近辺に収まる見込み。AWS の請求額と食い違ったらキャッチを差し替える。

**根拠より小さい数字は書かないこと。**

### S-2. 技術構成 ★最大の見せ場

- アーキテクチャ構成図
- 各要素の選定理由（`content/stack.md` から供給。原典は ADR）
- 拡張ポイントの図示

技術力が最大の訴求軸のため、経歴より前に配置する。

## 6. 目玉：リクエストの流れのアニメーション

要件の中核。`ArchitectureDiagram` コンポーネントに実装する。

**やること**

1. 構成図を SVG で描く
   `Browser → CloudFront → API Gateway → Lambda (Bref) → Laravel → Response`
   S3（静的アセット）は CloudFront から分岐する枝として描く
2. 光の粒がノード間を順に流れるアニメーション。ループさせる
3. 各ノードをクリック / タップすると選定理由がパネルで開く
   内容は `content/stack.md` から供給する（ハードコードしない）
4. 「拡張ポイント」を破線で表示
   - Lambda から DynamoDB / SQS / 外部 API
   - Bref X-Ray（将来）
   - 「要件が無い層は作っていない。必要になれば関数を足すだけで拡張できる」という
     設計判断の説明を添える

**やらないこと**

- 動きを他セクションに広げない。目玉は一つに絞る
- 他はスクロールフェードインに留める

`prefers-reduced-motion` を尊重し、アニメーションを止めても情報が読める状態を保つ。
