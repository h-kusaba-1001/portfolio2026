# AI-DLC / Inception 成果物

AWS が提唱する **AI-DLC（AI-Driven Development Lifecycle）** に沿って本プロジェクトを進めている。
Inception → Construction → Operations の 3 フェーズのうち、Inception の成果物をここに置く。

> **本プロジェクトにおける適用範囲**
> AI-DLC の Inception / Construction は、チームで画面を共有して進める
> 「モブエラボレーション」「モブコンストラクション」を前提とする。
> 本プロジェクトは個人開発のため、モブを AI との 1 対 1 の対話に置き換えて実施している。
> また、AWS が報告する生産性の数値は組織的な実践での値であり、本プロジェクトの規模とは前提が異なる。

---

## 1. Intent（意図）

サイトを見た人が、技術構成について直接質問したくなる状態をつくる。

制約: 月額固定費を限りなくゼロに近づける。

---

## 2. User Stories

| ID | ストーリー | 受け入れ条件 |
|---|---|---|
| US-1 | 訪問者として、サイトを開いた直後に何者かを把握したい | ファーストビューだけで職種・訴求軸が伝わる |
| US-2 | 訪問者として、技術構成と選定理由を見て技術力を判断したい | 構成図と、各要素の選定理由が閲覧できる |
| US-3 | 訪問者として、リクエストが裏でどう処理されるかを直感的に理解したい | 構成図上でリクエストの流れが可視化され、各ノードから理由が開く |
| US-4 | 訪問者として、経歴の要点を短時間で把握したい | 「やってきたこと」と「キャリアの変遷」が 1 スクロールで読める |
| US-5 | 訪問者として、今後どういう仕事をしたい人なのかを知りたい | 志向が明示されている |
| US-6 | 訪問者として、移動中にスマートフォンで読みたい | 全セクションがモバイル幅で破綻しない |
| US-7 | 運用者として、コードを触らずにコンテンツを更新したい | Markdown ファイルの編集のみで内容が変わる |

---

## 3. Units of Work（並行開発可能な作業単位）

| ID | 単位 | 依存 | 対応ストーリー |
|---|---|---|---|
| UoW-1 | 基盤構築（Sail + Laravel + Inertia + Tailwind + Bref + osls、デプロイ疎通まで） | なし | — |
| UoW-2 | コンテンツ基盤（Markdown → CommonMark → Inertia props） | UoW-1 | US-7 |
| UoW-3 | 静的セクション（Hero / やってきたこと / キャリア / これから / Contact） | UoW-2 | US-1, US-4, US-5, US-6 |
| UoW-4 | **構成図アニメーション**（リクエストの流れ + ノード別選定理由 + 拡張ポイント） | UoW-2 | US-2, US-3 |

UoW-3 と UoW-4 は UoW-2 完了後に並行可能。

---

## 4. Bolt Plan

各 Bolt は数時間〜1 日を想定。**Bolt ごとに AI が計画を提示し、人間が承認してから実行する。**

| Bolt | 内容 | 完了判定 |
|---|---|---|
| B-1 | UoW-1: ローカルで Laravel + Inertia が起動する | `sail up` で http://localhost に Inertia ページが表示される |
| B-2 | UoW-1: osls + Bref でデプロイし、CloudFront で公開 | 公開 URL にアクセスできる |
| B-3 | UoW-2: Markdown 読み込み導線 | `content/*.md` の編集が画面に反映される |
| B-4 | UoW-3: 静的セクション一式 | 全セクションがモバイル幅で読める |
| B-5 | UoW-4: 構成図アニメーション ★最重要 | 流れが動き、ノードから理由が開く |
| B-6 | 最終確認 | 完了条件（requirements.md §7）を全て満たす |

**B-5 に最も時間を配分すること。** ここが訴求の中核であり、他は手段。

デプロイ（B-2）を早い段階に置いているのは、動く URL を先に確保して、
以降の確認を本番環境ベースで回すため。
