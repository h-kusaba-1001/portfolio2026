# 技術構成

このサイトは AWS Lambda の上で動く Laravel です。
データベースを持たず、コンテンツは Markdown を Laravel が読んで返しています。

選定理由の原典は [ADR](../docs/architecture-decisions.md) を参照してください。
以下は構成図の各ノードから開くパネルの原稿です。

## CloudFront

Lift プラグインの `server-side-website` 構造で構築。
静的アセットは S3 に置き、動的リクエストは Lambda に流しています。
CloudFront を手で組まずに済み、アセットの S3 アップロードも自動化されます。

独自ドメインは取得していません。デフォルトドメインで足ります。

## S3

静的アセット（JavaScript・CSS）の置き場所です。
バケットはパブリックアクセスを全てブロックしており、**直接は開けません**。
CloudFront だけが読める設定にしています。

Vite がファイル名にハッシュを付けるため、内容が変われば URL も変わります。
そのおかげで 1 年間キャッシュさせても、更新が反映されないという問題が起きません。

CloudFront のアクセスログも、別のバケットに 14 日だけ保管しています。

## API Gateway

HTTP API のワイルドカードルートで、全リクエストを Lambda に流しています。

## Lambda (Bref)

PHP を Lambda で動かすための Bref 3.0 を使用。
完全従量課金で、この規模なら無料枠に収まります。

**固定費が跳ねるのは Lambda ではなく、RDS・NAT Gateway・ALB です。**
そこを避ける設計にしました。

## Laravel + Inertia.js

現時点ではルーティングとコンテンツ配信のみを担う薄い層です。
掲載内容が読み取り主体で、サーバ側の処理を要する機能要件が無いため、
API もビジネスロジックも結果として存在していません。禁じているわけではなく、
必要になった時点で足します。

Inertia はサーバがページコンポーネント名と props を返す仕組みなので、
Laravel 層そのものは必須です。薄いのはビジネスロジックであって Laravel ではありません。

## デプロイ: osls

Serverless Framework は v4 から、個人利用でもアカウント登録かライセンスキーが必須になりました。
「固定費ゼロ」という前提と噛み合わないため、v3 の OSS フォークである osls を採用しています。

osls は Bref のメンテナが維持しており、Bref 公式ドキュメントも移行を推奨しています。

## 拡張ポイント

要件が無い層は作っていません。必要になれば足せる状態は保っています。

- **DynamoDB** — 書き込み機能が必要になったとき。従量課金のまま維持できます
- **SQS** — 非同期処理が必要になったとき
- **Bref X-Ray** — クエリや外部呼び出しまで含めた分散トレースが必要になったとき

いずれも `serverless.yml` に追記するだけで足せます。
